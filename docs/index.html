听见HEAR

听见是 iPhone 上的实时语音翻译应用，支持双向识别、随说随译、说话人区分和译文朗读。 识别、翻译和声音克隆可以分别选用本机或局域网服务，配置好本地模型后可离线使用。

01

功能架构

整个 App 是一条五段式信号通路：采集 → 断句 → 识别 → 翻译 → 朗读。 每一段都做了引擎抽象，可以独立选择「手机本地」「系统自带」或「局域网云端」，三者可以任意组合。

功能清单

01交互模式

  • 实时翻译模式　轻点麦克风开始收音，App 会在选定的两种语言间判断方向。再点一次停止。
  • 对话翻译模式　轻点左侧或右侧的语言圆圈开始，再点同一个圆圈停止。点另一侧会先收完当前语段，再切换语言。
  • 模式切换　底部横向滑动或点击圆点切换模式，应用会记住上次使用的模式。
  • 翻译气泡　先显示原文，再逐步显示译文。等待修正时保留已有译文，修正成功后标出变化。
  • 编辑和重试　长按气泡可修改原文并重译，也可选择复制译文。翻译失败且有原文时，可直接点「重试翻译」。
  • 灵动岛和锁屏　设置中可选「展示译文」或「展示原文和译文」。展开灵动岛或查看锁屏时可读译文，暂停收音后显示暂停状态。

02语音识别

  • 本机 SenseVoice　支持中文、英语、日语和韩语。实时识别可在语句结束前回显原文。
  • 苹果自带　iOS 26 或以上提供系统听写，适用语种随设备可用的语言资源变化。
  • 云端语音识别　从「模型管理 → 云端模型 → 语音识别」选择服务支持的 SenseVoice、Whisper 或 SenseVoice + Whisper。
  • 区分说话人　云端由服务器提供说话人模型。本机 SenseVoice 需带 CAM++ 模型文件，在「语音识别」里开启「实时翻译时区分说话人」。
  • 说话人资料　点击头像可修改姓名、性别、常用语言和口音。总结可引用已命名的说话人。

03翻译

  • 本机 Hy-MT2　使用 1.8B GGUF 模型。前台可用 GPU，切入后台可用 CPU 继续，同一份模型可直接沿用。
  • 云端 Hy-MT2　通过局域网调用电脑上的翻译服务。
  • 苹果自带　iOS 26 或以上可选，语言包可由系统下载。
  • 结合上文翻译　利用相邻语段帮助处理接续词，译文只对应当前语段。
  • 术语配置　从首页菜单打开「术语配置」，按「原文=译文」维护词表，翻译时加入匹配当前原文的条目。

04朗读与声音

  • 声音输出位置　在「功能设置 → 朗读」选择手机扬声器或耳机。使用耳机时可分别指定左右耳听哪种译文或静音。
  • 播报时机　扬声器模式通常在停止收音后朗读。App 切到后台时暂停播放，识别、翻译及克隆生成可继续处理。
  • 声音克隆　在「朗读」里开启后，可以选本机 ZipVoice 或云端 Qwen3-TTS。本机 ZipVoice 适用于中英文。
  • 样本和系统朗读　优先使用这句的参考音频。同页中有已确认的相同说话人和同种语言时，可复用该说话人的合格样本。样本不足或克隆声音不可播放时，用系统声音朗读。
  • 图标状态　克隆生成中显示转圈，音频开始输出时喇叭变绿。播放结束后显示灰色喇叭，可在「显示声音图标」中关闭灰色图标。
  • 静音与缓存　播放前裁掉克隆音频首尾的长静音，保留句中的停顿。已有缓存首次读取也会处理。

05会话与历史

  • 历史记录　每页对话可独立存档，保留原文、译文及说话人资料。
  • 大模型总结　配置服务提供商后可选会议纪要、简明摘要、行动项清单、双语要点或沟通访谈记录，结果支持编辑。
  • 继续使用　异常中断的总结会标记为失败，可再次生成。

06模型管理

  • 本地模型　分别管理 SenseVoice、Hy-MT2 翻译模型和声音克隆（ZipVoice）。
  • 下载和导入　下载时可在模型页暂停并继续。Hy-MT2 选 GGUF 文件，SenseVoice 和 ZipVoice 可选正确的模型文件夹或 ZIP。
  • 云端模型　填通用服务地址后可测试三个服务的就绪状态，也可为单个模型单独配置地址。
  • 未配置时　从「引擎管理」选择未配置的引擎，会打开对应的模型配置。

07设置项

  • 语音识别　选择手机或耳机麦克风，并调整语音增强、说话灵敏度与断句停顿。
  • 翻译与总结　配置上下文、灵动岛与锁屏显示和大模型总结服务。
  • 朗读　管理声音输出位置、左右耳、声音克隆及声音图标。
  • 语言和日志　「显示语言」可选简体或繁体中文，应用内呈现的中文原文与译文按该设置显示。可查看日志并控制是否记录对话内容。「记录推理耗时」默认关闭，开启后可查看首条预览、整句识别和整句翻译的计时。收到 iOS 崩溃报告后，可从运行日志菜单导出。

08稳定性与同步

  • iCloud 同步　可将设置和历史同步到 iCloud 云盘。同步的设置包括显示语言、区分说话人、记录对话内容和记录推理耗时的开关，以及声音输出偏好。运行日志文件留在本机。需要访问授权时，可从功能设置授权；暂时失去访问后会在后续同步重新检查。
  • 本机资源　收到内存警告后会卸载本地模型。停止收音和朗读后，应用会释放音频会话。
  • 云端繁忙　正式识别和译文优先，服务忙时预览短暂退让，正式请求在限定次数内重试。
  • 排查问题　运行日志可区分识别、翻译、声音克隆、连接和模型加载相关问题。
02

技术架构与关键技术点

客户端使用 Swift 和 SwiftUI。本机识别和说话人区分通过 FluidAudio，翻译通过 llama.cpp，声音克隆通过 sherpa-onnx。云端调用由 CloudClient 管理。

关键技术点

AUDIO

采集与重采样

AudioCapture 从 AVAudioEngine 采样，经 AVAudioConverter 转成 16 kHz 单声道 Float32。引擎启停与采样处理使用独立队列。

收音用 .playAndRecord，单独朗读用 .playback。音频路由变化时重新检查采样格式，停止收音并结束朗读后释放音频会话。语音增强可在设置中开关。

VAD

自动断句算法

Segmenter 按帧估计音量与停顿，同时参考内置 Silero 人声检测。判断为非语音时会抑制起句和识别请求。检测器不可用时使用音量阈值。断句时长按采样率和帧长换算。

起句保留前置音频，收尾清理多余静音。对话模式允许较短的回答。识别后还会过滤无意义文本和与语种不符的结果。

ASR

识别引擎编排

本机 SenseVoice 通过 FluidAudio 打开 Core ML 模型。苹果听写通过 LiveTextEngine 编排。中文简繁转换用于显示和复制。

云端组合方案先返回 SenseVoice 原文，再按队列与结果质量决定是否运行 Whisper 校正。校正后重新翻译成功才替换原文与译文，等待期间保留已有译文。

本机 CAM++ 与云端说话人模型提供声纹向量，App 在当前对话中跟踪说话人并保存手动补充的姓名等资料。

LANG

语种自动判断

实时模式结合引擎的语种、文本字符和当前两种语言判断方向。对话模式按用户选择的语言收音，切换语言前先交付上一轮音频。

应用提供 13 种语言条目，选择器会按当前识别引擎的能力过滤。本机 SenseVoice 当前提供中文、英语、日语和韩语。

MT

翻译模型与提示词

本机 Hy-MT2 的上下文为 2048，批大小 256。正式翻译最多生成 512 个 token，实时预览最多 256 个。前台优先 GPU，后台使用 CPU。

PromptBuilder 构建中英文提示词，并加入与当前语段匹配的术语。推理使用模型对话模板和参数 top_k 20 / top_p 0.6 / temperature 0.7。

CTX

上下文连贯翻译

每句独立推理，清空上次的 KV cache。开启「结合上文翻译」时，TranslationSource 用相邻原文处理断句处的接续词，仍只翻译当前语段。

预览更新时保留已有译文，最终译文成功后按变化范围高亮。

TTS

朗读与空间音频

系统声音通过 AVSpeechSynthesizer 朗读。分配到单耳时，将合成音频交给 AVAudioPlayerNode 并调整声道。

克隆播放根据播放器的渲染进度点亮喇叭，完成后解除播放状态。输出无法启动或停滞时尝试系统朗读。

VC

声音克隆

本机使用 sherpa-onnx 运行 ZipVoice-Distill INT8 和 Vocos。云端 Qwen3-TTS 通过 llama-server 使用参考音频和参考文本生成译文声音。

生成及缓存读取都会校验音频，去掉首尾长静音并在裁切位置短暂淡入淡出。句中停顿保留，近乎无声的结果会触发回退。

CONCURRENCY

并发与取消

LiveSession 在主线程维护会话。识别、翻译、说话人区分和克隆使用独立的任务协调，旧任务的迟到结果无法覆盖新状态。

实时原文与译文预览分别消费最新快照。停止收音先交付尾句，整句识别和翻译优先于预览。

MODEL

模型下载

本机 Hy-MT2 使用 GGUF。SenseVoice 与 ZipVoice 可导入目录或 ZIP，导入时检查必需文件，并在成功后替换旧模型。

下载状态可见，可暂停与继续。应用控制多个模型一起初始化的内存峰值，加载和完成提示都显示在对话页同一分隔线。

MIRROR

下载源自动选择

HostPicker 先查 Cloudflare 的 cdn-cgi/trace，读出 loc= 判断国家： 在国内切 hf-mirror.com，否则用 huggingface.co；查询失败或超时则两个源同时 HEAD 探测， 哪个先通用哪个。结果在进程内缓存，下载失败时 reset() 重新选择。

STORAGE

会话存储

每次对话一个 JSON 文件（Application Support/Conversations/<uuid>.json）， 另有 index.json 索引记录标题、条数、预览、语种与总结状态。 索引损坏时 rebuildIndex() 重建；启动时 recoverInterrupted() 把残留 .generating 状态的总结标记为 failed。

一份对话可挂多套总结模板（summaries[templateID]），互不覆盖。

SYNC

iCloud 同步

iCloud 同步使用云盘目录、文件协调和目录访问授权。App 可使用自己的容器，或借助系统文件选择器授权目录。失效的授权在后续同步重新检查。

同步包括 settings.plist、conversations/ 与 manifest.json。对话按修改时间与同步基线合并，设置通过同步指纹判断更新来源。模型文件与 API Key 保留在本机。

STABILITY

崩溃保护与自恢复

CrashGuard 结合启动标记、内存警告和崩溃日志辅助排查。内存紧张时卸载本地模型，后续按所选引擎重新准备。

麦克风启动异常时尝试恢复音频会话，设备路由变化时重新检查采样。App 切到后台时停止朗读。

LOG

日志系统

App 运行日志支持查看、搜索和按容量轮转，并可选择是否记录对话内容。

Windows 内测服务当前默认记录相应的原文或译文，可用 HEAR_LOG_CONTENT=0 关闭服务默认记录。

SECURITY

凭据与隐私

本机引擎在手机上推理。启用局域网引擎时，相关音频或文本发给配置的服务。使用大模型总结时发送用于总结的文本，启用 iCloud 同步后则会同步历史和设置。

API Key 优先存入钥匙串。钥匙串不可用时，App 将其保存在受文件保护且排除备份的本机文件。

03

云端模型服务

「听见」的在线能力分两类，职责完全不同： 一类是自建的局域网模型服务，把识别、翻译、声音克隆三个模型搬到自家电脑上跑，手机通过 Wi-Fi 调用； 另一类是外部大模型 API，只用于给对话生成纪要，不参与翻译链路。

局域网模型与对话总结

局域网服务接收语音识别、译文翻译或声音克隆请求。外部大模型服务用于对话总结，可按需在 App 设置里配置提供商。

启动时按类型选模型

下载仓库根目录的 start-hear-cloud.bat 并在 Windows 启动。单独下载的脚本默认获取最新服务文件；放在仓库内时使用当前工作副本。

默认由 SenseVoice 先输出原文，Whisper 后续校正。菜单可选 Whisper base、small、medium 或 large-v3，首次默认 small。 翻译可选 Hy-MT2 1.8B、7B 或 30B-A3B，克隆可选 Qwen3-TTS 0.6B 或 1.7B。 每项直接回车或 5 秒无操作时沿用上次选择，首次使用脚本默认值。

电脑和 iPhone 连同一个局域网后，在「功能设置 → 模型管理 → 云端模型」填写启动窗口显示的 HTTPS 地址，并点「测试连接」。Whisper 档位由 Windows 启动脚本管理。

prompt 是 App 拼好的，与本地翻译用的是同一套格式（使用当前语段与匹配的术语）；服务端只做转发， 由 llama.cpp 套用模型自带的对话模板。

关键技术点

PROBE

客户端自动识别服务类型

CloudClient 区分听见总服务与直接连接的 llama-server。总服务提供识别、翻译、克隆和健康检查，单独的 llama-server 可提供翻译或克隆接口。

FALLBACK

地址回退链

单个模型可设置独立地址，必要时尝试通用服务地址。常规部署只需填写 Windows 窗口显示的总服务 HTTPS 地址。

请求繁忙时保留所选引擎，正式请求按限定次数重试。预览利用冷却时间降低请求密度。

HEALTH

健康检查与状态判定

/health 报告各模型的就绪状态、可选识别方案和可用模型信息。启动阶段可能显示加载中。

如果 App 连不上，先用手机浏览器打开同一个 HTTPS 地址，再检查 App 的 iOS 本地网络权限和 Windows 的专用网络防火墙设置。新版 Windows 服务启动时会自动更新不符合规范的 HTTPS 服务证书，沿用现有签发根。

TLS

同一个端口，http 和 https 都能用

启动时，服务为局域网访问准备 HTTPS 证书。手机优先使用控制台给出的 HTTPS 地址。监听地址变化时服务会检查证书，并在需要时更新。

TLS 握手在连接工作线程处理。空闲的 HTTPS 长连接到期会正常关闭。服务端可通过 HEAR_REQUIRE_TOKEN=1 为推理请求启用访问口令。

BOOT

先占端口，再后台预热

HTTP 总服务先开始监听，识别权重和其他模型按启动流程准备。可以用 /health 等待实际需要的模型就绪。

ASR

云端识别的三套方案

sensevoice 只用 SenseVoice，whisper 只用 faster-whisper。默认组合 sensevoice+whisper 先返回 SenseVoice 的原文，再按条件校正。

组合方案的实时预览用 SenseVoice。正式识别和翻译优先，预览、校正、说话人区分和声音克隆使用其余并发名额。

DETAIL

踩过的坑与对应处理

识别器统一接收与指定采样率对应的 PCM 数据。客户端断开时，服务会收尾释放请求。

Windows 日志会区分上传超时（408）、推理繁忙（503）和等待后端超时（504），对应接口会写入相关诊断日志。

PARAM

采样参数透传

翻译请求由 App 构建提示词，总服务转发给 llama-server。正式请求通常最多生成 512 个 token，带预览标记时限为 256。

PROXY

识别可外接到别的服务

配置 HEAR_ASR_URL 后，总服务可以把语音识别请求作为 multipart WAV 转发到兼容的 /v1/audio/transcriptions 接口。

BACKEND

硬件后端矩阵

Windows 启动脚本默认使用 GPU。翻译可选 GPU、CPU 或兼容设备上的 OpenVINO NPU；声音克隆支持 Windows 脚本的 GPU 或 CPU 模式。

默认语音识别在 CPU 上运行。实际速度取决于模型档位、设备和同时进行的任务。

DEPLOY

一键启动

Windows 推荐运行仓库根目录的 start-hear-cloud.bat，由脚本准备服务文件、运行环境和模型。首次下载耗时取决于网络与模型大小。

局域网只需访问总服务端口 8000，8081 和 8082 默认只在电脑本机监听。占用端口时，脚本仅自动处理能确认归属的旧服务实例。

DIAG

错误要说清楚原因

空闲连接回收不会显示请求失败。真实超时可按日志区分上传阶段和后端阶段。Windows 启动后的自检页与 /health 可辅助确认地址及服务状态。

PERF

性能参考

首轮模型下载及加载时间与实际识别耗时分开。可通过运行日志查看正式识别、翻译或声音克隆的耗时。

B · 外部大模型 API 仅用于对话总结，不参与翻译链路

用户可以在「功能设置 → 翻译与总结 → 大模型 API」配置并切换服务。 App 会将整页对话连同原文、译文和已标记的说话人整理后，根据所选模板生成总结， 结果写回对话文件，支持二次编辑。

总结的数据流向

生成总结时，App 会把对话文本发送给所选提供商。公网总结地址使用 HTTPS；局域网自建总结地址可在 App 内显式确认 HTTP。

总结模板

01高效会议纪要（德鲁克）

  • 按「卓有成效的管理者」的有效会议理念组织，固定七段式结构：会议目的 / 参与方与语言 / 讨论要点 / 达成的结论 / 行动承诺（表格）/ 未决问题与风险 / 下一步。行动项表格要求「事项 · 负责人 · 截止时间 · 备注」，对话里没明确的写「待定」。

02简明摘要

  • 三到五句话说清这次对话讲了什么，再列五条以内的关键要点，适合快速回顾。

03行动项清单

  • 专门抽取可执行的事项与负责人，输出为可勾选的清单。

04双语要点对照

  • 左右对照呈现原始语言与译文要点，方便核对术语与语气是否准确。

05沟通访谈记录

  • 按访谈结构整理问答过程，保留追问与回答的对应关系。

执行生成机制

  • 同一对话可并存多套模板的结果，互不覆盖。
  • 生成在后台任务中执行，用 beginBackgroundTask 申请后台运行时间。
  • 配置不完整时（没加 API、没选模型、没读到 Key）会给出具体是哪一项缺失，而不是笼统报错。
  • 结果可手动编辑后保存，并记录所用模型与更新时间。
