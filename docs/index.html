听见HEAR

一个跑在 iPhone 上的实时语音翻译应用。麦克风里的声音被切成句子、识别成文字、翻译成另一种语言， 再用合成的声音读出来。不联网、不上传、不需要账号——识别、翻译、声音克隆三个环节都能在手机本地跑， 也可以把其中几环搬到自己的电脑上，手机通过局域网调用。

01

功能架构

整个 App 是一条五段式信号通路：采集 → 断句 → 识别 → 翻译 → 朗读。 每一段都做了引擎抽象，可以独立选择「手机本地」「系统自带」或「局域网云端」，三者可以任意组合。

麦克风取流、重采样到 16 kHz 单声道、语音增强与路由管理。

STAGE 2

自动断句

按 30 ms 帧做能量 VAD，判断起句、静音收尾，产出可提交的语音片段。

语音识别

系统语音朗读译文，或用克隆音色把译文念出来。

引擎可选 识别　Whisper / SenseVoice / 系统听写 / 云端 翻译　Hy-MT2 本地 / 系统翻译 / 云端 朗读　AVSpeechSynthesizer / Qwen3-TTS 克隆 默认　全部本地，离线可用
三个环节可以任意组合：全本地（全离线，不用开电脑）、全云端、或者一半一半。 全本地的配置是「识别：SenseVoice（快）或 Whisper（准）」+「翻译：本地引擎 MT」+ 「声音克隆：本地引擎 Qwen」。代价是内存——Hy-MT2 约 1.1 GB、Qwen3-TTS 两个文件约 800 MB、 SenseVoice 约 240 MB，三个同时常驻对内存小的机型有压力。 App 的对策：声音克隆模型放到最后加载（等其它模型就绪）、用不到的模型自动卸载、 翻译切到云端就卸载本地翻译模型、收到内存警告时全部卸载、 麦克风起不来时先卸掉声音克隆模型再试。内存吃紧就先用 SenseVoice + 本地 MT， 需要原声朗读时再把 Qwen3-TTS 打开。

功能清单

01交互模式

  • 实时翻译模式　点一下麦克风开始，直接说话，App 自动判断说的是哪种语言并翻成另一种；再点一下停止。
  • 对话翻译模式　左右两个「按住说 XX」按钮，按住说对应语言，松开即翻译并播报。
  • 双向互译　13 种语言任意配对（zh / en / ja / ko / ar / fr / de / es / ru / pt / it / th / vi）。
  • 模式切换　底部左右滑动切换，底部圆点指示当前模式，点圆点也能直接切。 上次用哪个模式会记住，下次打开还是那个模式（这个模式只存在本机，不跟 iCloud 走）。
  • 暂停不丢内容　整句话还没说完时（气泡是虚线的）按暂停，那句也会留下来继续翻译，不会消失。
  • 气泡式对话　左右分栏气泡，源语言侧在左、目标侧在右；实时气泡随识别持续刷新。
  • 结果可编辑　长按某句可改原文并重新翻译、复制原文或译文。
  • 点气泡即朗读　正在朗读的气泡带描边与声波动画。

02语音识别

  • Whisper　本地最准，large-v3 turbo，标点与长句最好。
  • SenseVoice　本地最快，约 240 MB，中英日韩粤，说完立刻出字。
  • SenseVoice + Whisper 校正　推荐，先出快结果，空闲时用 Whisper 复核，明显有差异就替换，被改过的句子带魔法棒标记。
  • 系统听写　iOS 26+，说话时逐字显示，说完由 Whisper 定稿。
  • 云端识别　可选，走自家电脑上的服务，方案可指派。
  • 语种自动判断　识别结果与文字脚本不一致时自动改判另一侧语言。

03翻译

  • 本地 Hy-MT2　腾讯 1.8B GGUF，llama.cpp 跑在 GPU 上。
  • 云端翻译　可选，调用局域网里的 llama-server。
  • 系统翻译　iOS 26+，调用系统 Translation 框架。
  • 上下文连贯翻译　可开关。开启后参考最近两句已完成的原文，代词与语气更连贯。
  • 自定义术语表　每行「原文=译文」，人名、公司名、专业词强制按表翻译。
  • 采样参数　Hy-MT2 官方推荐值：top_k 20 / top_p 0.6 / temperature 0.7。

04朗读与声音

  • 译文朗读　可开关；朗读期间麦克风自动静音，杜绝回声串音。
  • 左右耳　耳机模式下可指定译文进左耳或右耳，另一侧播放原文或静音。
  • 声音克隆　在「朗读」栏里单独开关（默认关）。模型在「引擎管理 → 声音克隆」里选： 云端服务引擎（默认）或本地 Qwen3-TTS 0.6B（喂一段参考音频 + 参考文本，用这个音色念译文）。 列表里没有「苹果自带」——系统本身没有声音克隆的能力。
  • 克隆失败会明说　云端克隆服务不可用时弹一条「声音克隆服务不可用，已改用系统声音朗读」， 并在日志里记下原因，不会悄悄换成系统声音。
  • 云端和本地一样干净　参考音频一律先降噪再送进模型（不然环境音会被一起学过去， 念出来有杂音）；采样参数也和本地完全一致 （top_k 20、top_p 0.6、用模型默认温度）—— 服务端不传的话 llama-server 会用自己那套偏松的默认值，念出来会跑调、夹杂杂音。
  • 生成中会转圈　克隆声音要等电脑算完（好几秒）， 这时候气泡里的喇叭变成一直在转的半圈，一眼就知道「马上就好」。
  • 等得到再放弃　云端克隆要等电脑那边算完，最多等 60 秒； 同一句只发一次请求（发两次会排队，等太久就超时退回系统声音）。
  • 没有样本时说清楚原因　克隆要拿说话人的原声当样本： 太短（不足 1.5 秒）或太长（超过 12 秒）的那一句， 会自动借用同一种语言上一句完整的声音（还是同一个人的音色）； 实在拿不到样本时，日志会写明是「录音时开关是关的」还是「这句太长了」， 而不是笼统一句「没有声音样本」。
  • 克隆只会说几种语言　参考音频用源语言（可以是英文）， 念出来的是译文那门语言（跨语言克隆）； 阿拉伯语、泰语、越南语这些目前不在克隆模型的语种里，会直接说明。
  • 克隆缓存　内存 LRU 60 条 + 磁盘 WAV 长期留存，按 SHA256 命名。 键里带参考音频的指纹：同一句话换了说话人不会命中上一个人的缓存。
  • 音色选择　系统朗读优选高质量音色，过滤个人音色与 novelty 音色。

05会话与历史

  • 历史记录　每次对话独立存档，列表页显示标题、条数、预览与语种。
  • 多模板总结　5 套模板：德鲁克式会议纪要、简明摘要、行动项清单、双语要点对照、沟通访谈记录。
  • 总结可编辑　生成结果可直接改写后保存。
  • 中断恢复　异常退出后残留的「生成中」总结会被标记为失败，不会永远转圈。

06模型管理

  • 四类本地模型　Whisper、SenseVoice、Hy-MT2 翻译模型、Qwen3-TTS 克隆模型，分别下载与导入。
  • 断点续传　网络中断自动续传，网络类错误最多重试 8 次，指数退避。
  • 镜像加速　自动探测所在网络，国内走 hf-mirror，海外走 huggingface.co。
  • 本地导入　从「文件」App 直接导入 .gguf 或模型目录。
  • 在线模型　识别 / 翻译 / 克隆三个模型各自独立配置地址，支持「测试连接」。
  • 页签跟着引擎走　三个引擎（识别 / 翻译 / 克隆）里只要有一个是本地引擎，就停在「本地模型」； 都是在线引擎、或者在线 + 苹果自带混着用，就默认「在线模型」。
  • 状态可视　每个模型行直接显示「未配置 / 正常 / 异常」，异常时给出具体原因。

07设置项

  • 说话灵敏度　6–24 dB，环境吵就调高。
  • 停顿时长　400–1500 ms，调短出结果更快。
  • 声音来源　手机麦克风或耳机麦克风。
  • 运行位置　GPU 或神经引擎（Apple Silicon）。
  • 语音增强　回声消除 + 降噪 + 自动增益，可关。
  • 日志　可开关，上限 10 / 50 / 100 / 500 MB，支持在 App 内查看。

08稳定性与同步

  • iCloud 同步　把设置与历史对话同步到 iCloud 云盘里的「听见」文件夹，位置固定，不用用户选； 打开开关不会弹选择框，只有系统还没给过云盘权限时才在设置里给一个「授权一次」的入口。
  • 双向合并　按修改时间判定谁新推谁，删除记录双向合并，设置用哈希指纹判断。
  • 崩溃捕获　未捕获异常 + 6 类信号，崩溃现场写入本地日志。
  • 异常退出检测　结合崩溃记录、内存警告、退出前可用内存三项判断，避免误报。
  • 麦克风自恢复　启动失败自动重试，音频路由变化时重装采样回调。
  • 停了就把麦克风放开　停止实时翻译（或按住说话松手）以后， 会停用音频会话把麦克风让出来——不然音频会话一直停在「可录音」状态， 手机上别的录音 App 录出来是静音。正在朗读的时候不会停会话（避免切断声音）， 等读完再放。
  • 云端失败降级　云端引擎出错自动切回系统引擎并重启会话，不中断使用。
  • 日志看得到开始与结束　云端克隆、云端翻译这类要等好几秒的操作， 都会先记一条「开始」，结束后再记一条带用时的「结束」；关键节点同步落盘， 中途崩溃也查得到停在哪一步。

关键技术点

AUDIO

采集与重采样

用 AVAudioEngine 的 installTap（format 传 nil 跟随真实格式）取流， 再用 AVAudioConverter 统一转成 16 kHz / 单声道 / Float32；格式变化时重建转换器， 容量按 frameLength × ratio + 64 预留，避免爆音。

每次取整 100 毫秒（16 kHz 正好 1600 个采样）： 采样数不能被整除时，转到 16 kHz 会攒出零头，转换器偶尔错开一小截， 听起来就是「刺刺」的杂音。

音频线程上只做最少的事：取到的样本立刻送去后台线程， 系统听写、其它识别引擎的喂样本都在后台做—— 音频线程是实时线程，哪一下没赶上就会漏音。

会话类别按「要不要麦克风」来定：正在收音是 .playAndRecord， 只是朗读就降成 .playback——.playback 不占麦克风， 手机上别的 App（录屏、录音机）才录得到声音。 改类别只在没有声音在放的时候做：改类别会打断正在播的声音。

播放引擎用完就停：朗读结束 0.6 秒后把 AVAudioEngine 停掉。 引擎一直开着会一直占着音频输出，别的 App 放声音会跟我们互相干扰。

语音增强（setVoiceProcessingEnabled）会独占麦克风： 同时录屏、录音的时候，别的 App 拿到的声音会又刺又碎。 设置里可以关掉，界面上也写清楚了。

语音增强用 setVoiceProcessingEnabled（回声消除 + 降噪 + AGC），同时把 ducking 配置为 enableAdvancedDucking: false、duckingLevel: .min——否则朗读时系统会把麦克风压低。

麦克风起不来时的兜底：刚激活音频会话，硬件有时还没准备好， 输入格式会短暂地是 0×0。这时不直接报错，等最多 0.5 秒再看； 真的起不来会把「麦克风启动失败」弹出来并写进日志，不会闷着不动。

语音增强只在收音的时候开：不收音就停掉音频会话，麦克风整个让出来。 而且 Apple 要求改语音处理之前必须先停会话，所以顺序是 「停会话 → 设语音增强 → 按需要激活会话」——开着会话改，轻则报错、重则录出来发闷发杂。 设置里把语音增强关掉，收音中也会立刻生效（重开一次麦克风）， 录屏时想临时关掉不用先停一次翻译。

VAD

自动断句算法

按 30 ms / 帧（480 采样） 逐帧分析，参数全部可在设置里调：

  • 噪声底：取最近 100 帧（约 3 秒）dB 的第 10 百分位，钳在 −75 ~ −25 dB；阈值 = max(噪声底 + 灵敏度, −50 dB)。
  • 起句：需连续 5 帧（150 ms） 超阈值才判定开始说话，并保留说话前 300 ms 的 preroll，避免吞掉第一个字。
  • 收尾：静音时长达到「停顿时长」（400–1500 ms）或整句超过 15 秒 即结束；尾部静音裁掉，只留约 200 ms。
  • 静音线：max(噪声底 + 灵敏度×0.5, 本句平均音量 − 18 dB)；本句音量用 EMA 更新（0.97 × 旧值 + 0.03 × 新值）。
  • 丢弃：有声时长不足 400 ms 的片段直接丢掉，不进识别。
ASR

识别引擎编排

WhisperKit 用 openai_whisper-large-v3-v20240930_turbo（CoreML，非 GGUF 量化），中文前置提示 「以下是普通话的句子，使用简体中文。」，输出经 StringTransform("Hant-Hans") 转简体。 关键采样参数：temperature = 0、noSpeechThreshold = 0.6、 compressionRatioThreshold = 2.4、logProbThreshold = −1.0、 sampleLength = min(224, max(24, 秒数 × 15))。

识别结果还要过两道闸：confident() 按分段平均 logprob 与 noSpeech 概率过滤幻觉， isMeaningful() 再用字幕/广告语黑名单过滤「字幕」「点赞」「Subtitles by」这类无意义输出。

SenseVoice + Whisper 校正的判定：去掉标点、空格与大小写后算编辑距离， 距离 ≥ 2，或 距离 = 1 且较短句长度 ≤ 8 才算「明显不同」； 不同则以 Whisper 为准并重译、标记魔法棒图标、把朗读位置回退到该句重读。

LANG

语种自动判断

不依赖模型的语言标签，而是统计识别文本的 Unicode script 区间——中日韩 / 西里尔 / 阿拉伯 / 泰 / 拉丁， 命中率 ≥ 0.6 才判定为该语言；CJK 文本里夹的连续拉丁字母按 1 个字计， 避免「Nginx」这类词把中文判成英文。

识别引擎返回的语言与文本脚本不一致时改判另一侧；lastLangID 记住上一句语种，作为下一句的 fallback。

参考上面的信息，把下面的文本翻译成English，注意不需要翻译上文，也不要额外解释：

术语表只注入命中的条目（大小写不敏感的包含匹配），避免无关术语污染上下文。

CTX

上下文连贯翻译

每次翻译前调用 llama_memory_clear(ctx, true) 清空 KV cache—— 每句独立推理，这样不会因为上一句的生成把下一句带跑偏，也保证了延迟稳定。

「上下文」是通过提示词文本注入实现的：开启后取最近 2 句已完成的原文， 按「参考上面的信息…」的模板拼进 prompt，历史本身不进模型状态。

TTS

朗读与空间音频

双耳（pan = 0）直接走 AVSpeechSynthesizer.speak；单耳则用 synth.write(u) 拿到 PCM 缓冲， 转成硬件当前输出格式后交给 AVAudioPlayerNode 并设置 player.pan 播放，实现「原文进左耳、译文进右耳」。

细节：超时保护 5 + 字符数 × 0.45 秒；bestVoice(for:) 过滤掉个人音色与 novelty 音色， 取 quality 最高的一个；输出音量做峰值归一（峰值低于 0.5 时放大到 0.85）；设备路由变化时把 connectedFormat 置 nil 重建引擎。

VC

声音克隆

走 llama.cpp 的 mtmd 音频多模态接口，需要两个 GGUF：Qwen3-TTS 骨架（0.6B Q4_K_M） 与 mmproj 语音 tokenizer（Q8_0），输出 24 kHz。加载参数： n_gpu_layers = 999（或 CPU 时 0）、embeddings = true、 n_ctx = n_batch = 2048、线程数 min(6, 核数 − 1)。

参考音频的处理链路：16 kHz PCM → denoise()（80 Hz 一阶高通 + 20 ms 分段取能量最低的 20% 估底噪， 做 0.5 倍软门限）→ 写临时 WAV → mtmd_helper_bitmap_init_from_file 得到 speaker_ref， 配合参考音频里那句原话（ICL 上下文）一起进模型。

采样 top_k 20 / top_p 0.6 / temp −1（用模型默认）/ seed = UInt32.max， 骨架部分用贪心采样（取最大 logit）；每次生成前后清 KV cache（该管线不支持复用 KV）。 输出做峰值归一 + 头尾 5 ms 淡入淡出，峰值低于 0.0005 判为静音并退回系统声音。

CONCURRENCY

并发与取消

LiveSession 是 @MainActor final class: ObservableObject； SpeechRecognizer / SenseVoiceRecognizer / LlamaTranslator / GGUFVoiceCloner / CloneCache / CloudClient 全部是 actor； 音频采集回调跑在 hear.audio.segmenter 队列，引擎启停在 hear.audio.engine 队列。

取消机制是三级：runGen（停止会话时 +1，作废在途结果）、loadGen（防旧加载覆盖新状态）、 EpochCounter（取消预览翻译）与 CancelFlag（取消整句翻译）。 实时预览分两条独立循环：previewLoop 与 previewTranslateLoop， 各自用单飞标志，互不等待，只翻「最新一份」文本。

MODEL

模型下载

翻译模型从 Hugging Face tencent/Hy-MT2-1.8B-GGUF 取：先调 /api/models/{repo} 拿文件列表， 按 Q8_0 > Q6_K > Q5_K_M > Q4_K_M 的优先级挑量化版本，排除 1.25bit / 2bit / IMATRIX 变体。 WhisperKit 走 WhisperKit.download(variant:downloadBase:progressCallback:)， 镜像通过 setenv("HF_ENDPOINT", …) 切换。

下载器 FileDownloader 用 URLSessionDownloadDelegate：网络类错误（−1005 / −1001 / −1003 / 连接丢失） 最多重试 8 次，指数退避 min(2ⁿ, 30) 秒， 用 NSURLSessionDownloadTaskResumeData 续传；请求超时 120 秒、资源超时 2 小时。

导入的模型会校验是否包含 AudioEncoder.mlmodelc / TextDecoder.mlmodelc / MelSpectrogram.mlmodelc。 模型路径在 UserDefaults 里存相对路径——重装 App 后沙盒绝对路径会变。

MIRROR

下载源自动选择

HostPicker 先查 Cloudflare 的 cdn-cgi/trace，读出 loc= 判断国家： 在国内切 hf-mirror.com，否则用 huggingface.co；查询失败或超时则两个源同时 HEAD 探测， 哪个先通用哪个。结果在进程内缓存，下载失败时 reset() 重新选择。

STORAGE

会话存储

每次对话一个 JSON 文件（Application Support/Conversations/<uuid>.json）， 另有 index.json 索引记录标题、条数、预览、语种与总结状态。 索引损坏时 rebuildIndex() 重建；启动时 recoverInterrupted() 把残留 .generating 状态的总结标记为 failed。

一份对话可挂多套总结模板（summaries[templateID]），互不覆盖。

SYNC

iCloud 同步

免费账号自签的 App 拿不到 CloudKit 权限，因此走 iCloud 云盘里的一个文件夹。 位置固定为「听见」（App 名字）：优先用 App 自己的 iCloud 容器 （FileManager.url(forUbiquityContainerIdentifier:)），没有就用之前授权过的文件夹， 在里面放一个「听见」。用户不用选目录，也不用改目录，界面上也不显示同步位置。 老版本用的「听见同步」文件夹会在升级后自动改名成「听见」。

打开开关不会再弹「请选择文件夹」：位置永远是「听见」。 授权用的是普通书签（URL.bookmarkData(options:)， iOS 上没有 macOS 那种带安全权限的选项），关键在于 书签解析出来的 URL 实例要用到底：同一份书签解析两次会得到两个 URL， 只有开过 startAccessingSecurityScopedResource() 的那一个能动里面的东西， 之前的版本解析了两次，于是每次都以为「没权限」，又要让用户重新选。 现在权限在整个 App 运行期间一直开着， 只有系统完全没给过云盘权限时，设置里才会出现一个「授权 iCloud 云盘」的按钮—— 界面上不再有任何说明文字和提示气泡，点一下授权即可。

同步三类数据：settings.plist（设置，26 个键，用 SHA256 指纹判断是否被改过； 「实时翻译 / 对话翻译」这个模式只存在本机，不跟 iCloud 走， 否则每次启动都会被云盘里的旧值改回去； 含在线模型：通用服务地址、三个模型各自的地址、识别方案、用不用云端翻译/克隆）、 conversations/<uuid>.json（历史）、manifest.json（各页修改时间、删除记录、设置哈希）。

方向判定：对话按每页 updatedAt 谁新推谁；删除用 deletedConversations 字典两边合并； 设置是三态——只有 iCloud 改过而本机没改过才 pull，两边都改以本机为准。读写走 NSFileCoordinator， 文件未下载到本机时识别 .文件名.icloud 占位并触发下载，最多等 5 秒。

从 iCloud 拉下来的设置直接换上，不用重开 App：语言、灵敏度、词表、引擎、 在线模型地址都会立刻生效；改地址之后 2 秒内自动同步一次， 同步进行中改的会等这轮结束再补一次，不会漏。

模型文件与 API Key 不参与同步。

STABILITY

崩溃保护与自恢复

NSSetUncaughtExceptionHandler 捕获未捕获的 ObjC 异常（取前 15 帧调用栈）， 另注册 SIGABRT / SIGSEGV / SIGILL / SIGTRAP / SIGFPE / SIGBUS 信号处理器； 写完日志后恢复默认处理器并 raise，让系统照常生成崩溃报告。 信号处理器内不做 queue.sync，直接用 FileHandle 追加写，避免死锁。

异常退出检测用标记文件 hear-running.json（含启动时间、是否收到内存警告、退出前可用内存）： 下次启动时文件还在即判定异常退出，但只有有崩溃记录 / 收过内存警告 / 退出前可用内存 < 400 MB 三者之一才提示，避免用户划掉 App 时误报。

音频侧：麦克风启动失败重试 3 次（重置音频会话、关掉语音增强再试），仍失败则卸载已加载的克隆模型再试； AVAudioEngineConfigurationChange 通知触发重装 tap（重试 2 次）； 停止引擎放到后台队列，避免蓝牙切换模式时卡住主线程。

LOG

日志系统

全局 hearLog(_:_:) 可从任意线程调用，日志写 Documents/hear-log.txt， 格式为 [MM-dd HH:mm:ss] [I/W/E] 内容；内存里保留最近 3000 条，启动时只读文件尾部 1 MB。 上限可选 10 / 50 / 100 / 500 MB，超过一半即轮转为 hear-log.old.txt，两份合计不超过上限。

SECURITY

凭据与隐私

大模型 API Key 优先存钥匙串（kSecClassGenericPassword，service com.hear.llm， kSecAttrAccessibleAfterFirstUnlock）；自签 App 没有钥匙串权限时自动降级到 FileKeyStore（Application Support/llm-keys.json， completeFileProtectionUntilFirstUserAuthentication，并标记 isExcludedFromBackup 不进 iCloud 备份）。

整个 App 的默认路径是数据不出设备：识别、翻译、克隆都在本地推理； 只有开了云端引擎或调用外部大模型 API 才会出网，且走的是用户自己填的局域网地址或用户自选的 API。

03

在线模型服务

「听见」的在线能力分两类，职责完全不同： 一类是自建的局域网模型服务，把识别、翻译、声音克隆三个模型搬到自家电脑上跑，手机通过 Wi-Fi 调用； 另一类是外部大模型 API，只用于给对话生成纪要，不参与翻译链路。

两类服务的边界

自建云端模型服务是「把模型换台机器跑」，接口与本地引擎一一对应，手机端无需任何改动； 外部大模型 API是「对话结束后的增值能力」，只有配置了 API Key 才能用，缺失时只影响总结功能，不影响翻译。

关键技术点

PROBE

客户端自动识别服务类型

App 不要求用户手工区分端口。往地址发一个 GET /health：返回里带 asr / mt / clone 字段的判定为总服务（有识别接口）；只带 status 的判定为单独 llama-server； 探测失败不写缓存，下次还会再问一次。

判定为 llama-server 时：翻译走 OpenAI 兼容的 /v1/chat/completions，克隆走 /tts， 而识别直接跳过——单独的模型服务没有识别接口，App 会明确提示「这个地址不提供语音识别，请用 8000 的总服务地址」。

FALLBACK

地址回退链

每个模型可以单独配地址，也共用一个「通用服务地址」。请求时按 模型专属地址 → 通用地址（8000，会转发给真正干活的模型服务） 的顺序依次尝试， 第一个成功的即采用；全部失败才把最后一个错误抛给界面。

这意味着即使某个模型单独配的地址没起来，只要总服务活着，功能依然可用。

协议只有一种：只用 https。用户只填 192.168.x.x:8000 的话， App 会自动补上 https://，测试连接之后把补好之后的地址回显出来。

HEALTH

健康检查与状态判定

服务端探测后端 llama-server 时，把状态分成三档：就绪（200）、加载中（503 且响应体含 loading—— llama-server 模型还没加载完，这是「活着但在准备」，不是「连不上」）、连不上。

探测结果缓存 2 秒：不缓存的话后端没起来时每次 /health 都要等 3 秒 + 3 秒， 手机 5 秒就超时了，会被误报成「连不上」。

TLS

同一个端口，http 和 https 都能用

电脑上第一次启动服务时，make_cert.py 会用 cryptography 生成一张自签证书（SAN 里带上本机所有局域网 IP、127.0.0.1 和 localhost）。 私钥只留在本机的 server/certs/ 里，不进仓库。

总服务在 8000 端口上同时接两种协议：接到连接先偷看第一个字节， TLS 握手的第一个字节固定是 0x16，是 TLS 就套上 TLS，否则按普通 http 处理。 这样浏览器自检页面还能用 http 打开，App 则一律走 https://。

握手放在工作线程里做（这一步很关键）。 偷看字节和 TLS 握手都不在 accept 线程里： 放在那里的话，一个连上不吭声的客户端、或者一个握手慢的手机， 就能把整个服务堵住（每个最多 5 秒），手机那边表现就是「有时卡住了」。 实测：旧写法被 3 个慢连接堵住时，一个 /health 要等 14.6 秒； 现在是 0.02 秒。

用 HTTP/1.1 长连接：手机可以复用同一个连接， 不用每发一个请求就重做一次 TLS 握手。握手次数少， 「握手失败」（certificate unknown、EOF）和卡顿都跟着少。

证书会自己更新：换了网络、路由器重新分配了 IP 之后， 旧证书里没有新 IP，手机会直接拒绝（certificate unknown）。 现在服务启动时会检查证书里有没有本机当前的 IP，没有就地重新生成一张。

App 侧只对内网地址（私有网段、.local、localhost） 放行自签证书，公网域名照常走系统校验； 同时用自带的会话而不是系统共享会话，因为共享会话没法挂证书处理程序。

内网自签证书是按内网地址放行、不校验主机名的： 证书里的 IP 是生成那一刻的，电脑换网络、IP 变了也照样连得上， 不用每次换网络都重新装证书。

地址写成 http:// 也会被自动换成 https://， 根本没写协议的（只写 192.168.x.x:8000）则补上 https://。

本地网络权限：访问电脑上的服务需要系统的「本地网络」权限， 而系统的授权框只问一次——用户选了「不允许」以后 App 再也弹不出来， 只能自己去 设置 → 隐私与安全性 → 本地网络 → 听见 里打开。 大部分人不知道这个开关在哪儿，所以 App 会自己认出来（系统拒绝时返回的是 「操作不被允许」errno 1，跟「电脑没开机」不是一回事）， 然后弹一个提示把步骤写清楚，还能一键跳到设置页。 触发时机：刚把引擎换成云端、点「测试连接」失败、以及用云端引擎时请求被系统拦下。

声音克隆可以直接回原始 wav：手机在请求头里带 X-Hear-Audio: wav， 服务就回 wav 原始数据（Content-Type: audio/wav），省掉 base64， 手机那边内存占用小很多；不带这个头的老客户端仍然收到 JSON（audio 是 base64）。

三个端口都要清干净：Windows 上绑在具体地址（127.0.0.1） 的套接字会优先于绑 0.0.0.0 的。 所以上一个窗口没关干净、残留了一个监听 127.0.0.1:8082 的旧 llama-server 时，总服务（走回环）连到的是旧实例， 手机（走局域网地址）连到的是新实例——两边对不上， 克隆出来的声音是乱的、还慢十倍。 现在启动脚本会把 8000 / 8081 / 8082 三个端口一起清掉， 并且 /health 里直接报出后端跑的是哪个模型，一眼能看出有没有连错。

自检脚本 server/test_api.py：在 Windows 上直接测本机服务， 不经过手机、不经过 App，用来分清「是服务端的问题还是 App 的问题」。 python test_api.py health 看服务状态； python test_api.py clone --wav 参考.wav --text "Hello" 用一段中文声音念英文， 成功的话会存成 clone_out.wav，双击就能听。

证书由服务自己保证：hear_cloud.py 启动时发现 server/certs/cert.pem 不在，就地生成一份（SAN 带上本机所有局域网 IP）。 Windows 的 start-windows.ps1 和启动脚本会在服务起来之前先生成一次， 生成失败会明确报错并给出安装 cryptography 的命令，不再静默跳过。

没有证书时，TLS 握手会打到 HTTP 的解析器上，日志里会出现一条 400 和一段乱码。 现在乱码会被拦下来换成一句「收到一段二进制内容（不是 HTTP 请求），已忽略」， 并直接说明多半是没证书——不是编码问题。

证书没生成 = 手机连不上：App 只走 https， 所以 make_cert.py 必须成功跑过一次（start-windows.ps1 会自动跑， 失败会明确报错）。少了证书时服务仍然起得来，但只说 http， 此时 TLS 握手会打到 http 的解析器上，日志里会出现一条 400 和一行乱码—— 那不是乱码问题，是没证书。

BOOT

先占端口，再后台预热

主线程立刻把 8000 端口监听起来并 serve_forever，让手机连过来不会吃「拒绝连接」； 识别模型的加载、翻译/克隆后端的探测、启动自检全部放到后台线程，不阻塞请求处理。

识别模型（faster-whisper）是懒加载 + 后台预热的：第一次要下载几百 MB 权重， 期间 /health 会如实返回「加载中（第一次要下识别模型）」，下完变成「就绪」。 权重缓存到 ~/.cache/huggingface，只下一次。

ASR

云端识别的三套方案

由 App 在请求头 X-ASR-Scheme 指定，服务端按它执行，也可以用环境变量 HEAR_ASR_SCHEME 设默认值：

  • sensevoice　只用 SenseVoice（ONNX，CPU 也能跑，约 230 MB），最快。
  • whisper　只用 faster-whisper，最准但慢一些。
  • sensevoice+whisper　推荐。SenseVoice 先出结果，Whisper 再复核；两者文本不同以 Whisper 为准。

实时预览走 X-ASR-Preview: 1，此时组合方案只用 SenseVoice，不跑复核——预览要的是快。 SenseVoice 的输出带 <|zh|>、<|NEUTRAL|> 这类语言与情绪标记， 服务端负责解析出语种并清洗标签。

DETAIL

踩过的坑与对应处理

  • faster-whisper 必须喂 numpy float32 数组。给普通 list 它会当成文件去 av.open()，老版本 av 直接报 open() got an unexpected keyword argument 'metadata_errors'。服务端统一转成 ndarray，非 16 kHz 先线性重采样。
  • av 版本必须 ≥ 12，老版本没有 metadata_errors 参数，faster-whisper 解码会报错——这条写进了 requirements.txt。
  • 手机超时断开会刷 BrokenPipe 报错，两个处理分支都单独捕获，安静收尾。
  • 手机连的是 8081 / 8082 会失败：这两个端口默认只监听本机，手机访问不到。诊断文案里直接写明了这一点。
PARAM

采样参数透传

服务端向 llama-server 转发翻译请求时，携带与手机本地完全一致的采样参数： top_k = 20、top_p = 0.6、temperature = 0.7、max_tokens = 512、 stream = false。这样同一条句子走本地和走云端，输出风格不会变。

PROXY

识别可外接到别的服务

设置 HEAR_ASR_URL 后，服务端不再安装 faster-whisper，而是把 wav 转成 multipart/form-data 转发给 OpenAI 兼容的 /v1/audio/transcriptions—— 比如 whisper.cpp 的 whisper-server。转发的 multipart 请求体是手写拼装的， 边界串固定为 ----HearBoundary7MA4YWxkTrZu0gW。

BACKEND

硬件后端矩阵

llama.cpp 在不同机器上走的路子不一样，脚本通过环境变量切换：

  • NVIDIA 显卡　CUDA。
  • Intel Core Ultra 核显　Vulkan（--device Vulkan），兼容性最好，多模态（声音克隆）只能走这条。
  • Intel NPU　OpenVINO 后端（GGML_OPENVINO_DEVICE=NPU），官方文档验证机型是 Lunar Lake（Core Ultra 5 238V）。 限制：只支持纯文本模型、无状态执行（-np 1）、必须明确给 -c。
  • Apple Silicon　Metal。
  • WSL2　访问不到 Intel NPU，核显的 Vulkan 也不太稳，实际等同于纯 CPU。要吃满硬件必须原生跑 Windows。

默认分工：翻译走核显或 NPU，声音克隆走核显，识别走 CPU（faster-whisper int8）。

DEPLOY

一键启动

Windows 原生（推荐）：server\start-windows.ps1 自动下载 llama.cpp 的 Vulkan 版与 OpenVINO 版运行包、 三个模型文件（Hy-MT2 约 1.1 GB、Qwen3-TTS 两个文件约 800 MB），建 venv 装 faster-whisper， 起三个服务，最后打印一个局域网地址供填入 App。不需要编译、不需要 Visual Studio、不需要 WSL。

WSL2：server/start.sh，需要手动装 cmake / ffmpeg / python3-venv，实质是纯 CPU 运行。

防火墙需要放行 8000 / 8081 / 8082 三个入站端口。

DIAG

错误要说清楚原因

「测试连接」不只回答连不连，而是区分开：

  • ATS 拦截（不允许 http 明文）→ 提示需要 0.4.19 以上版本。
  • 端口没在监听 → 提示确认服务已启动，并说明 8081 / 8082 默认只在本机监听。
  • 超时 → 引导先用手机浏览器打开同一个地址：能打开说明是「本地网络」权限没给，打不开说明网络不通。
  • 503 且含 loading → 明确说「服务在加载模型（稍等几秒再试一次）」，而不是当成连不上。
  • 另有找不到主机、手机没联网、连接断开等分支。
PERF

性能参考

以 Intel Core Ultra 7 258V（16 核、Arc 130V 核显、NPU 48 TOPS）为例：

  • 翻译（Hy-MT2 Q4_K_M，核显 Vulkan）：一句十来字的英文约 1 ~ 2 秒，走 NPU 更快。
  • 识别（faster-whisper small，CPU int8）：10 秒语音约 1 ~ 2 秒。
  • 声音克隆（Qwen3-TTS 0.6B Q4_K_M，核显 Vulkan）：一句约 2 ~ 4 秒。

B · 外部大模型 API 仅用于对话总结，不参与翻译链路

用户可以配置多个大模型服务，在「设置 → 大模型 API」里切换当前使用的那个。 App 会把整页对话整理成带双方语言标注的逐句记录，套上模板提示词后送去生成纪要， 结果写回对话文件，支持二次编辑。

接口类型端点鉴权请求体
OpenAI 兼容OpenAI、DeepSeek、通义千问、Kimi、MiniMax、OpenRouter、Ollama 等 POST {baseURL}/chat/completions Authorization: Bearer {key} {"model":"...","temperature":0.3,"messages":[system, user]}
Anthropic POST {baseURL}/v1/messages x-api-key + anthropic-version {"model":"...","max_tokens":8000,"system":"...","messages":[user]}
两条链路不要混淆

翻译永远不走外部大模型 API。翻译只有三条路：本地 Hy-MT2、云端 llama-server、系统翻译框架。 外部 API 只在「生成总结」时被调用——它是把对话内容发出去的唯一路径，因此需要用户自己明确配置并填写 Key。 推理模型返回的 <think>…</think> 思考过程会被 stripThinking() 剥掉，不写进纪要。

总结模板

01高效会议纪要（德鲁克）

  • 按「卓有成效的管理者」的有效会议理念组织，固定七段式结构：会议目的 / 参与方与语言 / 讨论要点 / 达成的结论 / 行动承诺（表格）/ 未决问题与风险 / 下一步。行动项表格要求「事项 · 负责人 · 截止时间 · 备注」，对话里没明确的写「待定」。

02简明摘要

  • 三到五句话说清这次对话讲了什么，再列五条以内的关键要点，适合快速回顾。

03行动项清单

  • 专门抽取可执行的事项与负责人，输出为可勾选的清单。

04双语要点对照

  • 左右对照呈现原始语言与译文要点，方便核对术语与语气是否准确。

05沟通访谈记录

  • 按访谈结构整理问答过程，保留追问与回答的对应关系。

执行生成机制

  • 同一对话可并存多套模板的结果，互不覆盖。
  • 生成在后台任务中执行，用 beginBackgroundTask 申请后台运行时间。
  • 配置不完整时（没加 API、没选模型、没读到 Key）会给出具体是哪一项缺失，而不是笼统报错。
  • 结果可手动编辑后保存，并记录所用模型与更新时间。
